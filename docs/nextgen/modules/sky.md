## 設計の判断

- **薄明の整形（r3、atmosphere.js の twShape = GLSL の ngSkyTwShape、同じ式）**：RGB 3 波長の raymarch は日没後に
  方向によらず灰ラベンダーへ寄り、post の AgX がさらに彩度を落とす。«太陽側の残照以外» の空を輝度を保ったまま
  地平の淡い青 → 天頂の深い青（太陽の深さで濃く）、反太陽側にビーナスベルトの桃色（地球の影の上端 sin = −0.85·sy より上の帯、
  太陽 +2°〜−4°）、その下の地球の影の青灰、の色度へ寄せる（重み 0.9）。深い薄明（−4° より下）は地平を仰角で暗く（最大 0.38 倍）、
  −5° より下では残照の側も整形して地平の細い帯だけ橙（TWS.glow）に。色度の目標は «AgX の後で» 狙う色から逆算した。
- **太陽の項の太陽を −9° で止める（SUN_CLAMP_SY）**：物理の空は −11°〜−12° で崖のように落ち、利得の表（×2000 の上限）と
  CPU / GPU の段数の違いで崖の位置が食い違って照度が 20% 跳ねた。−9° より下は «−9° の空の形 × 単調に下がる利得»。
  利得の表は残照の側の利得込みで照度を測り直して目標に合わせる（2 回目の積分）。
- **月の照らす空（MOON_SKY 0.55・MOON_SKY_TINT ほぼ中立）**：物理の比のままだと露出 ×22 の夜空が «昼を暗くしただけ» の
  明るい青（AgX で R が 0 に潰れた #011e45）。key の月光（MOON_TINT の青）はそのまま。
- **夜の地面への空の光だけ ×2（NIGHT_FILL = 1）**：見える夜空は暗いまま、SH / AMB だけを夜に持ち上げる（月明かりの埋め）。
- **跳びの扱い（r3 で見つけた不具合）**：雲の模型の環境光の輪（_cloudy → SH → 環境光）が 0.25s ごとにしか回らず、
  跳びの後も前の時刻の環境光で雲が光った（正午 → 23:30 で夜空の照度が 15 倍のまま、撮る順で夜の明るさが変わった）。
  跳びでは輪を先に 4 回回す。濡れも跳びで即座に目標へ。
- **厚い甲板の環境光**：被覆 0.35→0.95 で上・下・底の環境光の色度を最大 0.9 中立へ（雨のブルーアワーが «晴れの夕空» に見えた）。
- **朝霧**：山を 5:45 → 6:09（日の出直後）へ。5:30（太陽 −7°）では反対の低い月に照らされた灰白の帯になっていた。
- 地平の整合の証拠の測り方を縮小（32×17 の 17 行目）と同じ核に。核が違うと残照の鋭い山で «測り方の差» を測る。

## 未解決・他への要望

- 乱層雲の下面に低い周波数の濃淡（ちぎれ雲・腹の高さの揺らぎ）を足す（雨の昼の «平らな灰の板»）。雲パノラマの ngSkyCloudBase で
  strat > 0.7 のとき底の高さを 2D の形のノイズで ±250m 揺らす案。重さは帯 1/32 なので小さい見込み。
- 黄金時間の «太陽の近くの積雲»：晴れの被覆の斑（ngCloudCover の焼いたノイズ）が太陽の方位に雲を置かない日がある。証拠の構図を雲のある方位へ
  向けるか、晴れの被覆の最小を少し上げる。
- 夜のドーム（high）が 0.6〜1.0ms で予算 0.70 を少し超える回がある。星の 3×3 セル探索を mid と同じ 2×2 に落とす案（未計測）。
- **post へ**：薄明・夜の色度の目標は stub の AgX（pmndrs ToneMappingMode.AGX）の後で決めた。post が別のトーンマップにするなら
  atmosphere.js の TWS・rig.js の MOON_SKY_TINT を見直す（sky-rig.mjs の 23:30 の色度のテストも）。
- **water へ**：真夜中 / 真昼の比が構図で 0.22〜0.45 に散るのは、夜の水面（stub）が空より明るい青になるため（night-fp-23.5 で水 #0a2a6a・空 #0b1a30）。
  水が NG.AMB / SH をどう使うかで夜の明るさが決まる。
- **core へ**：art-metrics の waterHue が noon-fp-down の全時刻（夜も）に掛かる。昼だけにするのが意図に合う。
