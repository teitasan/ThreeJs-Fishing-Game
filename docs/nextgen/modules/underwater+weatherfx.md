## 設計の決定
- **caustics は «ヘッセ行列を焼いて受け手で面積比»**（Evan Wallace の格子の面積比の解析形）。光子を 3m の面に撒く焼き込みだと
  (1) 時刻のフレームの線形補間で明線が二重写しになる、(2) 深さで焦点が変わらない。ヘッセ行列は線形なので補間・2 向きのタイルの和が
  «正しい波の場» のまま。D = 光路長 × (1 − 1/n)。RGB は n = 1.329 / 1.334 / 1.341
- water の `detailTile` は null なので、caustics は自分の周期スペクトル（spectrum.js、40 成分、空間 L = 7m・時間 8 秒で厳密に周期。テストで検査）
- 光柱：fog チャンクの «等方・影なし» の key の内散乱を、HG 位相（g 0.82）× 近景の影 × 太い筋に置き換える補正。
  **引く分は fog チャンク（ngWaterSegment）と同じ式**（(1 − T)·σs·iso/σt·e^(−kd·dAvg)、両端の深さの平均、cw なし）で数える。
  自前の積分で引いていた r1 では、深い斜面を見下ろす長い光路で core より大きく引いて画面が黒く潰れ、縁に白い線が出た（weedbed-uw）。
  さらに補正は «画素の 3 割より下へは削らない»（近似の誤差の保険）
- 光柱の予算：§6.3 の «半解像度 16 ステップ» は 1440p で 2.8ms（予算 1.2 の全部を超える）→ 解像度 0.3 × 12 ステップ（mid 0.25 × 8、low は解析）、
  焦点のタイルは最寄りの 1 層だけ読む（2 層の補間をやめた）、距離のぼけは 8 → 6 タップ。光柱は低周波なので分離ぼかし + 深さを見た 5 タップの合成で足りる
- 雨：位置は «粒の乱数・時刻・カメラ・風» だけの純関数（logic.js の rainDrop が JS の双子でテスト済み）。半分の粒を内側の円柱（半径 9m）へ（画面に効くのは近くの筋）。
  幅 1.6mm を 1.1 画素で下限、覆う割合は平方根で圧縮（物理の面積比のままだと 10m 先の α が 0.02 で雨が見えない）、長さは 1/40s 相当。
  四角の巻き方が視線に対して裏になるので **両面**（r1 は片面で 1 本も描かれていなかった）
- 着弾：柔らかい塊 + 放物線の 6 粒（ガウス）。王冠の弧・足もとの輪は数画素の板で «白い括弧» の記号に見えたので描かない
- 遠景の幕：殻 1 枚（55m、高さ 36m）。大きな尺度の濃淡で «雨の帯» が流れる（一様だと遠景に櫛の模様）。深度で先に捨てる
- 朝霧の板：**色は core の媒質そのものの源の放射輝度**（カメラ → 板の ngAirSegment の Lin/(1 − T)）。自前の E·HG + 空の放射照度は core の霧より暗く、
  板が霧の帯を逆に暗くしていた（差分 −3/255）。箱 140m（280m では視野に 2–3 枚しか入らない）、τ = ρ·100·var
- 蛍：桟橋の付け根に近い葦の上（placement.reeds）、2–4 秒周期の明滅（光るのは 2 割）、明るさ 0.45–1.15 倍・黄緑の幅の個体差
- 空の画素（線形深度 ≈ far）を水中から下・水平に見ているときは «無限に続く水» の色（fog チャンクと同じ式の閉形式）
- uniform の意味は本番と旧式（core のスタブの網目）で分岐（uCaustShape.x ≥ 1.5 が本番）。dispose で旧式の既定値へ戻す
- 開発用の口：`__ngUwNoRays`（光柱なし）・`__ngUwFxOff`（水中の Effect を無効。ベンチの «有効 − 無効»）・`__ngUwDbg`

## 自己批評（1 回）
撮った物：proof-final-720（18 + 2 枚）、proof-final-1440（7 枚）、game2（7 枚）。見つけた欠点と処置：
1. **雨の筋が 1 本も見えない**（片面で全部裏）→ 両面。さらに近くを濃く・長さ・α を見える値へ（修正）
2. **着弾が «白い括弧» の記号**（硬い縁の王冠の弧と輪）→ ガウスのしぶきの粒（修正）
3. **遠景の幕が森全体に一様な櫛の縞**（細かすぎる周期）→ 筋を 0.75m に、大きな濃淡で帯に（修正）
4. **weedbed-uw の深い斜面が黒く潰れ、縁に白い線**（光柱の補正の引きすぎ）→ core と同じ式で引く・3 割の床（修正）
5. **朝霧の板が見えない / 霧を暗くする**（薄すぎ・暗い色・疎ら）→ 密度・色を core の媒質へ（修正。ただし «層» としてはまだ控えめ）
6. **蛍が同じ明るさ・同じ色の点の群れ**→ 個体差（修正）
7. **光柱が 1440p で 2.8ms**→ 0.3 × 12・1 層（修正、≈ 0.46ms。光柱の筋は少し柔らかくなった）
8. 未修正：uw-golden（17:36）の水中がほぼ黒（lum 0.019）。key が低く水中の内散乱が小さい物理どおりだが、露出の順応の範囲の外。post と相談
9. 未修正：水面を下から見た «天井» が平らな灰緑の板（water の裏面）、uw-dock の左の深い所が彩度の高い青（terrain の湖底の色 × 水の霞）

## 未解決・他への要望
- **terrain（または core の CDLOD）**：水中のカメラから、深さ 4m より深い湖底のパッチが描かれないことがある（線形深度 = far）。
  underwater の Effect が «無限の水» で埋めて隠している（今回の weedbed-uw では湖底は描かれていた）
- **sky**：水中のカメラでドームの地平線より下（地面色のベージュ）に水の媒質が掛からない。上と同じく Effect が埋めている
- **post**：水中の黄金の時刻・夜の露出（uw-golden の lum 0.019・uw-night 0.0005）。水中は «暗い» のが正しいが、遊べる明るさの下限を post の順応で
- **water**：水中から見た水面の裏面（全反射の区域）に波の模様・屈折の揺らぎがほしい
- **core（Phase 2）**：朝霧を «層» としてはっきり見せるにはフロクセル（ngVolEnd）。カードは core の解析の霧の揺らぎだけを足している
- 予算の残り：underwater high の合成（距離のぼけ 6 タップ + 光柱の 5 タップ）が ≈ 0.8ms。次は距離のぼけを半解像度の前処理にする（≈ 0.3ms 減る見込み）
