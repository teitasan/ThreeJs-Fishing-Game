## 決めたこと（設計）

- **1 マテリアルで幹と葉**：BatchedMesh の LOD0 と LOD1 が同じ `trees-tree` を共有（プログラム 1 本 + 影の変種 1 本）。インポスター 1・シェル 1・山の影の焼き 1 = **5 本**（≤ 6）
- **LOD1 の束を距離で 3 本に（r4）**：BatchedMesh は全部のパスで全部のインスタンスの頂点を回す。反射（LOD1 は 18m まで）・影（箱の中）で捨てる木の頂点が半分以上あった。
  LOD1-a（反射の端の内：WORLD）・LOD1-b（影の箱の対角の内：NO_REFLECT + SHADOW_ONLY）・LOD1-c（外：NO_REFLECT、影なし）。LOD0 は NO_REFLECT + SHADOW_ONLY。同じマテリアルなのでプログラムは増えない
- **影だけの木の間引き（r4）**：視野の外の木は «影（根元から太陽と反対へ樹高 × cot(高度) + 4m、90m まで）の 4 点のどれかが視野の扇に入る» 時だけ影に出す（`_shadowReaches`）。太陽が低すぎる・key が無い時は全部出す
- **LOD0 の束も 2 本（r4）**：影の LOD0 の端（14m）の内 = 影・主、外 = 主だけ（外の影は代理の LOD1）
- **行列の空いた要素**：BatchedMesh の行列の `[3][3]` = 旗（1 普通・2 代理・3 影だけ）、`[0][3]` = 幹を太らせる倍率。頂点で読んで投影の前に戻す
- **夕方の霜（r2）**：原因は葉の «空の鏡面»（`ngSkySpecular` × Fresnel 0.53 の grazing）。夕方は地平の明るい空を全部の葉が写して白く粒立った。
  直し方（`ngTreeSkySpec`）：(1) 空の明るさを平均の空（ngSkyIrr）の 4 倍で頭打ち、(2) 樹冠の中の鏡面の遮蔽（水平に近い反射は隣の木に当たる、
  葉は密度 ≥ 0.5 として扱う）、(3) 粗さを考えた Fresnel（Fdez-Agüera）、(4) 樹冠の下では上向きの反射も遮る。成分ごとに切り分けて確かめた
  （`ngTreeMisc.w` の調べ物の表示：1–8）
- **山の影（r2）**：core の高さ場影は «地面が受け手・樹冠は遮蔽物» なので、森の中の点は樹冠の上面でも影 = 0 になる。遠景の森（インポスター・LOD1・シェル）は
  昼でも直接光が 0 だった（成分の切り分けで直接の拡散だけを出すと真っ黒）。木の 3 つのマテリアルは `hfShadow: false` にして、自前で
  «樹冠の上の方（地面 + 平均樹高 × 0.75）が受け手・地形だけが遮蔽物» の key の見えを 256²（±512m）に焼く（`trees-sunvis`、key が 0.35° 動くか 3 秒ごと）。
  頂点で 1 回読み、近景の影の外（`ngNearShadowR` の 0.8–1）だけ掛ける。core の解析の代わり（0.7–1）は割り戻す
- **樹冠の漏れ光**：近景の影の中の葉にも «上の葉を通った緑の光»（1 枚の透過 ≈ 10%）を足す（`ngTreeLeak`）。見上げた樹冠が黒い塊にならない
- **幹を太らせる**：placement の当たり `max(trunkR·h·1.15, 0.28)` は若木で見た目の何倍にもなる（当たりのある木 3226 本の 54% が最小値、最大 10 倍）。
  胸高を含む根元の帯（< 1.7m）を w 倍、そこから max(1.5m, 0.2h) で 1 + 0.3(w − 1) へ戻す。w ≤ 4（上限に当たる若木 135 本 = 4.2% は差が残る：要望 R-1）

## 課題

- **GPU（森を正面に見る構図）**：計画（効く順）
  1. LOD2（≈ 600 三角形：葉のカードを房ごとに 1 枚へ）を焼いて 55–100m を置き換える。同じ BatchedMesh の geometry を足すだけでプログラムは増えない。LOD1 の頂点 × 本数が 1/4 → main −3ms 見込み
  2. 反射（1.3–1.5ms）：LOD1 を距離の束に分けて反射は 18m の内の束だけ（済、2.8 → 1.4ms）。残りはインポスター：反射のインポスターの再ライティングから空の鏡面・透過を抜く（反射は半解像度で波に崩れる）
  3. 近景の影（森の構図で 1.5ms、3072² の正射影 1 枚）：視野の外で影が視野の扇へ届かない木は落とす（済：湖を見る構図の影 1.4 → 0ms）。LOD0 も «影の LOD0 の端の内 / 外» の束に分けた（済）。
     残り：影の LOD0 を 14 → 8m、影の箱の外側の帯の木は影の LOD1 の葉を半分に間引く
  4. TBDR（M1）で alpha テストの葉は隠面除去が効かない：葉の深度の前段（alphaTest の深度だけ → 色は depthFunc EQUAL）を core に要望（R-3）
- VRAM：インポスターの配列（albedo + normal、1024² × 16 層、mip）≈ 179MB。案：法線・厚み・AO を RGBA8 から RG8 + 別の半解像度へ、variant を 1 に
- 水の反射に写る森が縦の柵のように見えるのは water のスタブの読み方（trees の反射の RT 自体は正しい：`view('refl')` で確認）

## 他への要望

- **R-1（placement / 契約）**：`TRUNK_R_MIN = 0.28` は若木（h < 8m）で見た目の 4–10 倍。当たりのある木の 4.2% は幹を 4 倍に太らせても届かない。
  若木だけ最小値を 0.15 に下げるか、当たりを «幹 × 1.15» に合わせる方へ（trees は w の上限 4 で止めて差を数えている）
- **R-3（core / post）**：(a) TBDR 向けの葉の深度の前段（alpha テストの葉の重なりの断片を色の段で払わない）。(b) 日没直後の «林の中から夕空» のような極端な構図の局所の露出（post）
- **R-4（terrain）**：夜の林床（林の下の帯）が sRGB ≤ 3 に潰れる（trees を全部アルベド表示にしても 1.5% 残る）
- **R-2（core）**：高さ場影に «樹冠の上が受け手» の版（または地形だけの版）があれば、trees の山の影の焼き（256²・30 歩）が要らなくなる
